# I1：无额外 IK 的联合条件生成人体动作预检

更新：2026-09-29。状态：**开发预检，I1 Gate 未通过；同预算 PPO 尚未启动。** 研究对象为通用条件人体运动生成。用户已排除所有重定向后的额外关节 IK；此前全身后处理仅存放在 `reports/06_I1_joint_refinement_protocol.md` 作为失败诊断，不进入本轮训练集。

## 严格的数据流

同一预训练 OmniControl 权重、同一 Kick 文本、同一随机种子和同一原始右脚空间目标，比较：

1. **Base**：官方文本 + 右脚目标条件扩散采样 → 官方 G1 全身重定向。
2. **Joint conditions**：在采样**之前**再指定支撑脚、骨盆与上身关键姿态及出腿回收时刻；扩散采样阶段施加条件引导 → **相同的官方 G1 重定向**。

两组均不调用额外单腿或全身 IK，不修改控制器架构。官方 Kick 重定向把右手提示解释成另一个抓取任务，因此本轮不加入右手关键帧；否则两组重定向目标不一致。新条件中的支撑脚位置是设计假设，不能当成真实接触或测力标签。原始右脚 hint 与文本必须逐条一致。源代码：`scripts/r3_i1_generate_joint_conditions.py`、`scripts/r3_i1_generation_joint_compare.py`。

## 首版开发预检及失败

固定 8 条 Kick 开发动作、seed 42。直接密集叠加左脚、骨盆与上身提示后，右脚原目标误差从 Base 的 **0.161 m** 升至 **0.413 m**；左支撑脚帧间速度由 **0.00407** 升至 **0.00443 m/frame**，全身二阶差分由 **0.00202** 升至 **0.00226 m/frame²**。原目标与文本相同，结果文件 `results/r3_i1_generation_joint_human_pilot.json`。这一版本没有改善空间条件或接触代理，不进入正式训练。

失败的可能原因是条件过密，官方扩散引导按最大受约束帧数缩放，多提示会稀释原右脚目标的梯度。这个解释是代码和现象支持的**假设**，还需消融验证，不能写成已证实机制。

## 第二版：人体空间改善，机器人空间尚未改善

只在少数事件帧加入支撑脚、骨盆、头部与左腕提示；扩散引导中提高原右脚目标权重，并轻量惩罚支撑脚滑动和全身时间二阶变化。右脚回收帧使动作结束条件明确。所有这些梯度在**人体动作扩散采样**中起作用，未在机器人关节空间再求逆运动学。与首版使用同一 8 条开发样本，尚不能报告独立泛化。

同一 8 条开发动作的原始右脚目标误差 **0.161 → 0.011 m**，左支撑脚帧间速度 **0.00407 → 0.00061 m/frame**，总漂移 **0.0521 → 0.00475 m**，全身二阶差分 **0.00202 → 0.00181 m/frame²**。这些均为人体运动空间的量，不是机器人成功率；见 `results/r3_i1_generation_joint_v2_human_pilot.json`。

官方未修改的 G1 重定向对两组各 8 条均产生输出。对同一个原始生成前右脚目标，以机器人世界坐标衡量，重定向后踝部误差 **0.427 → 0.433 m**，没有改善；去除整体平移偏差后的误差 **0.135 → 0.039 m**，说明主要存在坐标/形态映射问题，但不能把去偏差指标代替真实目标成功率。结果见 `results/r3_i1_generation_joint_baseline_robot_audit.json` 与 `results/r3_i1_generation_joint_v2_robot_audit.json`。

进一步把**同一个研究性场景目标**注入两组仿真，使用同一现成 Kick tracker、256 环境、500 帧、同一初始动作编号，目标邻近成功率均为 **0%**。两组参考轨迹自身到目标的最小距离均值为 **0.171 → 0.249 m**（数值越小越好）。这八条开发样本在人体端指标有大幅下降，但尚未证明 G1 可执行条件保持；已训练控制器上的零成功也不能证明重新训练一定失败。评价文件为 `results/r3_i1_generation_joint_v2_{baseline,candidate}_fixed_tracker_eval.json` 与 `results/r3_i1_generation_joint_v2_reference_goal_audit.json`。独立审计发现该目标虽从生成前 hint 开始构造，仍使用了**基线生成动作与基线重定向根位置**确定比例和锚点，因而不是独立外部真值；两组共用同一个目标只保证仿真代理口径一致。它不是论文官方 Kick 得分，也不能作为正式 PPO 的目标定义。旧目标清单和参考文件目前仅在服务器上，需归档哈希后才能独立复查。

完整 100 条、种子 42/43/44 的生成与原始重定向审计已排入独立队列。正式同预算 PPO 将使用共同编号的参考动作与**未修改的官方 Kick 任务**，两组控制器从零开始，使用相同环境数、迭代数、种子和评估预算；官方任务成功率只回答训练数据的下游效用，不代替独立空间目标保持率。筛选失败仍计入全部 100 条生成输入的产出率。若没有足够共同编号动作或机器人端条件保持继续退化，应记录负结果与阶段阻塞，不得通过更换目标或分母掩盖。

继续推进的顺序：先检查人体空间条件误差、接触/时序代理与原文训练数据分布；若通过，再用未参与调参的 seed 43/44 与至少两类非 Kick 文本验证；随后对同编号成功重定向的 Base 和候选动作，用相同后处理、相同外部目标、从零训练且匹配环境数/迭代数/随机种子的 PPO 评估，并记录视频与完整检查点。若人体动作预检继续退化，应停在生成模块，不消耗 2×2000 轮 PPO 做无效对照。目标碰撞力和实际接触须另设可碰撞场景；当前 Kick 仅有目标邻近与足底代理。
