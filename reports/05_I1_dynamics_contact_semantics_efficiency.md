# I1 后续验证：执行、接触、语义与耗时

更新：2026-09-29。**判定：简单机器人空间 IK 后处理未通过 I1 Gate。** 本页仅记录通用条件人体运动生成课题。原始输入是同一组 100 个右腿 Kick 空间条件，OmniControl 采样种子 42/43/44；每组由官方重定向流程保留 64/64/63 条 G1 参考。修正只改 G1 右腿六个关节，人体生成动作、G1 根轨迹与左腿不变。未训练新的扩散模型或控制策略。

可核查的汇总清单为 `results/r3_i1_extended_validation_summary.json`，逐项记录底层结果文件的 SHA-256，并明确哪些指标只是代理或尚未测量。
`results/r3_i1_provenance_manifest_v2.json` 记录三个种子的原始条件文件、重定向脚本、G1 URDF、固定策略检查点、运行脚本、完成状态和 37 份服务器日志的路径、大小与 SHA-256。大体积生成轨迹与完整日志留在服务器，没有因复制到 GitHub 而获得独立公开复现许可；清单是来源收据，不等于完整资产归档或外部独立复现。

## 固定策略下的 Isaac 仿真执行

使用同一个已完成的 DreamControl Kick 控制策略，检查点 SHA-256 为 `e3c50fb6f36f59f89d1b4e788b1ba74cf1ff0cdde3dceff34a9d7765235f65c0`。每组原始和修正参考均使用 256 个 Isaac 环境、500 帧、评估随机种子 42；同组的初始 motion ID 相同，原始与修正目录的文件集合和官方 `glob` 加载次序相同。`scripts/r3_i1_play_eval_metrics.py` 在官方 `play_eval.py` 基础上加测关节误差、根位置误差、提前重置和踝部接触力，不更改检查点或训练器。

| 生成种子 | 官方目标邻近成功率：原始 → 修正 | 平均关节角误差：原始 → 修正 | 每环境提前重置：原始 → 修正 |
| --- | ---: | ---: | ---: |
| 42 | 80.08% → 0% | 0.0407 → 0.1828 rad | 0.074 → 6.000 |
| 43 | 83.98% → 0% | 0.0400 → 0.1664 rad | 0.066 → 5.590 |
| 44 | 93.36% → 6.25% | 0.0413 → 0.1537 rad | 0.180 → 4.961 |

这与先前 3D 几何目标误差由约 0.39–0.41 m 降至 0.12–0.13 m 的方向相反。结论是：**当前固定策略不能稳定执行这些简单 IK 修正后的参考**。这不是对机器人机械上绝无可能执行的证明；策略仅在既有 Kick 参考分布上训练，修正轨迹可能分布外。仿真后发生的重置会改变随后抽到的 motion ID，因此 500 帧总体指标虽然同起点，也不是逐轨迹全程一一配对。

参考轨迹本身也做了时间差分诊断，采用官方 Kick 动作库的 0.1 s 帧间隔，数据见 `results/r3_i1_temporal_quality_seed{42,43,44}.json`。三个种子每条轨迹新增的**峰值右腿关节速度**平均为 0.886、0.762、0.822 rad/s；新增的**峰值加速度**平均为 7.207、5.337、5.788 rad/s²。每条轨迹仅改右腿六关节，根轨迹与其余关节逐项保持不变。这些时间差分说明位置拟合确实引入额外运动需求，但未计算驱动扭矩或执行器热负荷；不可把它们当作硬件可执行性阈值。

导出文件的一致性另以 `scripts/r3_i1_pkl_field_integrity.py` 逐条核查：191 组原始/修正 `.pkl` 的字段集合一致；`global_pose` 的平移与旋转、`global_position`、`grab_idx`、`kick_pos` 和所有非右腿关节逐值相同，只有右腿索引 6–11 可变。结果见 `results/r3_i1_pkl_integrity_seed{42,43,44}.json`。`kick_pos` 在当前 DreamControl MotionLib 中只触发任务分支，运行时目标由关节正运动学另算，因而需要下述固定目标对照。

另外，官方 Kick 成功事件通过脚踝接近 `motion_lib` 内部的 `grab_pos` 判断，而 `motion_lib` 又从**当前动作输出**重新计算 Kick 峰值、目标和场景平移。它并未直接使用本实验保存的**生成前外部脚部 hint**；修正动作也会改变这个内部目标。这组官方成功率只能用来诊断固定控制策略的下游表现，**不能代替同一个外部目标下的 I1 条件成功率**。外部目标的几何检查仍见 [04_I1_feasibility.md](04_I1_feasibility.md)。

为排除上述目标重算带来的差异，进一步在种子 42 的 64 条轨迹上固定**原始轨迹推导出的** `grab_pos`、场景平移和事件时刻，使用同一检查点、同一初始 motion ID、256 环境、500 帧比较原始参考和三个右腿改动上限。代码中的 `--freeze-task-goal-from-dir` 只属于本研究的自定义诊断，不能当成论文官方评估；原始目标仍不是生成前的外部 hint。

| 种子 42：固定原始目标 | 原始参考 | IK ≤0.25 rad | IK ≤0.50 rad | IK ≤1.00 rad |
| --- | ---: | ---: | ---: | ---: |
| 目标邻近成功率 | 81.25% | 9.38% | 0% | 18.75% |
| 平均关节角跟踪误差 / rad | 0.0419 | 0.1820 | 0.1913 | 0.1813 |
| 每环境提前重置次数 | 0.070 | 6.598 | 6.492 | 5.910 |
| 左踝接触帧比例 | 0.903 | 0.646 | 0.710 | 0.688 |
| 右踝接触帧比例 | 0.749 | 0.145 | 0.269 | 0.276 |

所有四组输出均记录于 `results/r3_i1_frozen_goal_seed42_{raw,cap025,cap050,cap100}.json`。各组确有相同的 256 个初始动作编号与 128,000 次环境帧观测，但提前重置后每条轨迹的实际采样次数不同。这项控制实验说明：**即使固定内部目标，简单 IK 修正仍显著损害现有策略的执行**；不能把差异完全归咎于目标重算。也不能由此断言机器人硬件无法执行，因为策略未在修正动作上重新训练，且没有测量电机扭矩、功耗或目标碰撞力。0.25/0.50 rad 两档是在种子 42 上探索的敏感性诊断，尚无独立验证集。

## 接触：已测足部，未测目标撞击

Isaac 的踝部接触传感器提供了大于 10 N 的接触帧比例；仿真预检与三组正式运行都实际读到非零力。各组修正后，左踝接触帧比例由约 0.91 降至 0.68–0.72，右踝由约 0.75 降至 0.27–0.33，与提前重置增多一致。种子 44 的左右踝比例分别为 0.907→0.717 与 0.746→0.325。这只是身体连杆接触统计；当前 Kick 场景的打击目标是虚拟位置，没有可确认的实体打击目标或按接触对象分解的力，因此**目标撞击接触成功率尚不能从本实验得出**。几何脚踝原点低于地面的比例也只是一项代理，不能等同于脚掌网格穿透。

## 语义：踢腿事件代理

三组生成动作均使用同一句“右腿踢”文本，且 IK 完全不修改生成人体动作，因此人体端文本语义在原始/修正对照中按设计相同。机器人端预先定义探索性代理：右脚相对身体根节点位移至少 0.12 m、至少为左脚的 1.25 倍；修正后保持原位移的 80% 且峰值时刻差不超过 5 帧。三个种子的事件幅度/时序保留数分别是 **58/64、61/64、55/63**，并非全部保留。其余未重定向的 36/36/37 条没有机器人端结果。这一代理无法证明文本—动作匹配；只有一个文本类别时不能有意义地报告多文本 R-Precision 或 FID。

## 生成与修正耗时

官方 OmniControl 在服务器 GPU 1 的 NVIDIA RTX A6000 上，每组 100 条、1000 步去噪的进度条耗时 **413、415、415 秒**。额外的平滑 IK 对每条成功重定向动作进行 80 次 Adam 更新，在 CPU 上每条平均约 0.7–0.8 秒，具体逐种子数字见 `results/r3_i1_efficiency_audit.json`。该计时不含模型加载、重定向和 Isaac 仿真；不能称为完整流水线耗时。当前实现**增加**计算步骤，没有证据支持 I1 名称中的“Constraint-Efficient”性能收益。

## 关节改动上限敏感性

初始修正将每个右腿关节的改动上限设为 1.0 rad。另在种子 42 上探索 0.25 和 0.50 rad 上限，保持相同 100 条输入和 80 次优化；这是调参诊断，不是独立留出测试。较小上限的运动学条件误差与固定策略仿真结果见 `results/r3_i1_corrected_export_seed42_cap{025,050}.json` 和 `results/r3_i1_physics_seed42_cap{025,050}.json`。在原官方评估口径下，0.25 和 0.50 rad 上限的目标邻近成功率分别仅 0.39% 和 0%；关节平均绝对跟踪误差分别为 0.182 和 0.188 rad。因此简单缩小 IK 改动幅度未解决当前固定策略的跟踪退化。此处的目标仍会随输出重算，需结合下文固定原始目标的实验判断。

## 结论与下一步

简单的后置 IK 可以修正外部脚部目标的几何误差，却在固定控制策略下显著降低可跟踪性，故**不可作为已验证的完整 I1 创新点**。下一版应以**生成前外部目标**而非原始轨迹派生目标建立统一仿真任务；用关节速度/加速度、支持脚接触与控制器执行反馈约束生成或修正，而非只优化末端位置。再扩展到多个文本动作类别，并与同预算 Base、Constraint-Efficient 模块、Robot-Space 模块、Full I1 比较。若要证明物理接触，应加入具有碰撞几何体的目标并记录目标接触对、接触时间和冲量；若要证明动力学可执行性，应检查控制器训练后的成功率与执行器负荷。当前不进入依赖 I1 输出的正式 I2/I3 Gate。
