# 复现范围和缺失材料

核查日期：2026-10-17。固定官方跟踪仓库版本：`d48621620f522f5c901ef378d57db8df92d2888d`。

## 结论

当前工程复现的是 **PhyGile 公开跟踪代码的仿真运行及缩小数据规模的适配实验**。它不是完整 PhyGile 系统的已完成复现，也不能据此声称达到了论文主表性能。

| 论文组件 | 本次找到的官方材料 | 本工程状态 |
|---|---|---|
| GMT 跟踪器、MoE、PPO、两阶段训练配置 | 官方 tracking 仓库中存在 | 保存固定版本并适配现有仿真环境 |
| 262D robot-native 文本扩散生成器、TP-MoE | 检查的仓库中未找到实现或权重入口 | 已独立实现核心、文本接口、编解码与训练入口；未在真实配对数据上训练，作者数值约定仍未核验 |
| physics-prefix 在线续写和闭环适配训练 | 项目网页和论文有方法描述；检查的仓库中未找到完整入口 | 已执行随机权重候选的真实扩散—G1 仿真、拒绝和重放；短窗口接受反馈另测；已训练语义生成及 PPO 适配未完成 |
| 作者训练完成的 GMT 模型 | 仓库无发布的 checkpoint，检查时 releases 列表为空 | 本次策略从随机初始化训练 |
| 与作者实验一致的完整动作集及划分 | README 为作者机器上的路径示例；仓库有部分文本/难度 CSV | 未得到完整可用的数据包与对应划分 |
| G1 实机 | 用户明确不需要 | 不开展 |

可用性结论只针对上述日期检查的官方网页、仓库树和 releases；不推断作者没有内部代码或不会继续发布。

## 缩小实验的边界

运行使用服务器已有的 KungfuAthleteBot 来源、经过 GMR 和前向运动学处理的 G1 参考片段，以检查真实仿真训练链路。它们不是作者论文的完整训练集，也不是用户论文中舞蹈、转身、跳跃任务的完整基准。

当前 `moe_pilot.yaml` 从官方 Phase A 配置派生，保留公开代码的网络宽度与 PPO 参数。因为没有这些片段的作者难度标签，关闭课程、冻结与淘汰，关闭随机静态片段。**官方 MoE 默认只有第 1 个专家激活；关闭课程后不会自动激活全部专家。** 该配置因此是起始阶段的工程验证，不支持“完整多专家路由有效”的结论。

独立审查确认：官方配置加载器没有应用 YAML 中的 `rewards` 段。虽然 YAML 声明 global anchor position 奖励权重 0.8/std 0.2，实际训练和评估采用源码默认 0.5/std 0.25；有效环境参数以保存的 `env.yaml` 和运行日志为准。本实验未在运行中改动这一行为，不能声称执行了该 YAML 奖励覆盖。

本工程不把人为编造的难度标签当作官方标签。完整两阶段实验需要匹配的动作文件、课程 CSV 和足够的训练预算；完整 PhyGile 还需要生成器及前缀闭环代码/权重。

## 后续工程推进的范围

500/2000 轮与上一轮前缀报告均为历史快照。最新推进见 [课程评估与 262D 接口报告](../reports/PhyGile课程评估与262D闭环补全报告.md)。课程修复使用独立源码副本，旧的不可靠评估路径禁用；新服务完成独立进程逐文件、重置前评估，训练调用与 MoE 掩码均有工程验证。

新编解码在 24 个已有片段上检查往返与 URDF FK，采用本实现的显式语义约定。真实仿真事务通过独立进程重建并重放已接受历史，避开未经验证的直接状态写回。实际随机权重扩散候选全部拒绝；两个各 1 帧的人工保持姿态窗口仅检验真实接受与反馈，不能当作学习到的动作性能。完整课程标签、真实配对训练和闭环 PPO 仍缺。

## 源码与论文设置差异

- 官方安装说明的 clone 地址指向 `HybridRobotics/whole_body_tracking`；本工程实际使用 `Baojch/phygile_tracking`。
- 单动作示例引用的 `g1_training_future_conv_single.yaml` 不在所检查的固定版本中。
- 官方配置有 `cuda:1` 及 `/ssd/...` 路径；本工程显式改为当前设备与数据路径。
- 官方 YAML 的 `rewards` 段未被公开加载器应用；实际 global anchor position 权重 0.5/std 0.25，而非声明的 0.8/0.2。
- 论文附录的专家网络宽度为 `[2048, 1024, 512]`，所检查的 Phase A/B 配置中 `expert_hidden_dims` 为 `[512, 256]`。本工程保留公开代码设置，不能称其与论文超参数完全一致。
- 官方评估默认关闭训练失败终止，并在 `env.step` 自动重置之后读取指标。`runs_completed` 是回合数，不是动作成功数。任何本工程的评估必须说明终止条件、对齐时间和采样位置，不能把这个字段当成功率。

## 对用户论文的用途

PhyGile 的完整方法与“物理引导条件动作先验支持全身控制”有较强关联，值得作为研究对象。当前可直接利用的是公开 GMT 训练基础；只有获得缺失生成部分并完成同数据、同预算评估后，才适合将完整 PhyGile 列为正式的生成—控制对比方法。缩小实验分数不能填入正式基准主表。
