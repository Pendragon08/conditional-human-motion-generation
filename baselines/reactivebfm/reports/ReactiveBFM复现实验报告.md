# ReactiveBFM 复现实验报告

实验日期：2026-10-21。阶段：官方代码接入、数据核验和共享 GPU 限额训练验证。

## 1. 当前结论

**已完成官方完整规模文本条件 flow planner 的真实数据训练验证，尚未完成论文性能复现。**
本次使用官方 Kungfu 数据，单卡、单种子进行了 101 次 AdamW 更新；生成动作前缀替换和 RTC 训练路径均运行。
模型和优化器检查点已分别保存，重新加载后与训练结束时的参数哈希一致。
ScaleBFM 低层跟踪器完成官方 CPU 重建及 qpos→策略前向检查；没有进行 MuJoCo 动力学闭环、TensorRT 部署或真机实验。

## 2. 官方方案与本次范围

官方项目：[ReactiveBFM](https://github.com/zjwzcx/ReactiveBFM)，固定提交 `5a79d03cab824eb5917271ba720294e8a1b9d374`。
[项目主页](https://xiao-chen.tech/reactivebfm/)；[论文 v1](https://arxiv.org/html/2606.30362v1)。

方法以执行状态/运动上下文和文本为条件，用 flow matching 生成未来运动，逐步把训练中的真实前缀替换为模型前缀，以减少滚动生成时的分布偏差；RTC 对生成延迟进行条件化，低层策略负责跟踪规划轨迹。
本次保存的 `upstream/` 共 226 个文件、46,804,811 字节，官方文件未修改，逐文件 SHA256 见 `../upstream_manifest.json`。
新增脚本位于 `../scripts/`，负责下载、核验、限额执行、计数与保存证据。

| 项目 | 论文/官方公开方案 | 本次实际执行 |
|---|---|---|
| 生成模型 | 官方发布 DiT、512 隐层、16 层、8 头 | 保留完整架构，107,045,924 个可训练参数 |
| 运动表示 | 发布版 36D：root XYZ + xyzw 四元数 + 29 关节，60 Hz | 完全沿用；与此前 PhyGile 的 262D 资产分开 |
| 时域 | 发布默认上下文 25 帧、预测 50 帧、3 个 primitive | 完全沿用，共 175 帧训练样本 |
| 训练课程 | 官方默认 warmup 400k、总计 1M 步，8 卡×128 batch | warmup 25、总计 101 次更新，1 卡×2 batch |
| 前缀/RTC | 逐步替换模型前缀，RTC 默认最大延迟 6 帧 | 沿用；本次 cross_prob=0.1，官方默认为 0 |
| EMA | 官方训练支持/默认启用 EMA | 本次关闭，减少磁盘与显存占用 |
| 数据范围 | 论文总计约 37.14 h，包含 PhysHSI reaching 数据 | 下载公开的三套文本动作数据，共约 26.54 h；只训练 Kungfu |
| 目标位置条件 | 论文包含目标到达能力 | 本次固定提交的公开训练路径为文本条件，未补造目标条件或 reaching 数据 |
| 低层执行 | ScaleBFM 跟踪 + MuJoCo/TensorRT 运行路径 | 官方预训练 M 跟踪器 CPU 前向通过；动力学闭环未运行 |
| 论文评测 | 抗扰动、动作/控制性能等 | 官方 evaluation 目录仍标记待发布；未复现论文指标 |

论文 v1 的 20/40 帧描述、50 Hz 控制设置与当前公开代码的默认配置并不完全一致，本次以固定提交的发布代码为准。
未发现官方公开的 planner 预训练权重入口；仓库部署说明要求自行训练。ScaleBFM 权重属于低层跟踪器，不能当作已训练的 planner。

| 数据 | 动作记录 | 帧数 | train / val / test |
|---|---:|---:|---:|

检查范围：36D 形状、有限数值、长度一致性、文本存在、四元数范数、划分标识及完全相同动作数组的 SHA256 交叉。
所有动作数值有限、长度一致；四元数范数最大偏差约 5.96e-8；训练/验证/测试之间没有发现相同记录标识或完全相同数组。
这些检查**不能证明主体隔离、原始片段隔离、无近重复或物理可执行**。

保持官方 Mean/Std。其与重新计算的训练集统计不完全一致：mean 最大差异依次为 0.01213、0.00210、0.01111，std 最大差异均为 1.0。
常量通道处理等统计策略尚未核实，不能据此断言泄漏；也不能声称已独立验证仅用训练集统计。
具体结果见 `../results/data_audit_v1.json`。

Kungfu train 共 803 条，其中 116 条短于 175 帧，被官方 loader 排除，实际候选训练记录 687 条。
Kungfu test 共 44 条，其中 7 条过短，候选 37 条；辅助测试只固定使用前 8 条，没有用于反向传播或调参。

## 4. 环境与实验设置

服务器两张 RTX A6000。本次经授权共享物理 GPU1，保持原有进程运行。
CPU 线程 4；PyTorch 每进程显存分配上限为整卡 25%（约 12 GiB），实际占用低于此限制。

使用隔离 overlay 和已有只读包目录/DistilBERT 缓存，没有更改已有训练环境。
Python 3.10.21、PyTorch 2.5.1+cu121、NumPy 1.26.4、MuJoCo 3.3.7、Transformers 4.45.2。
这与官方推荐 Python 3.12、PyTorch 2.11+cu128 不同，因此属于**兼容性验证**。
完整依赖声明见 `../configs/env_spec.json`，独立执行记录见 `../results/document_witness_v1/`。
独立检查实际执行了 CUDA 运算、完整官方 DiT 前向和反向，没有执行优化器；不能把它单独算作训练。

首次作者检查把时间步错误传为浮点数，官方接口要求整数；只修正了检查脚本。失败与修正后的记录均保留，没有隐藏失败，也没有修改官方源码。

## 5. 真实训练结果

种子 42，batch=2，warmup=25，总更新=101，无 EMA。官方训练入口和损失保持原样；新增代码只记录标量、优化器更新次数和前缀选择次数。

| 检查项 | 结果 |
|---|---:|
| 实际 AdamW 更新次数 | 101 |
| 官方最后 step counter | 101 |
| 模型前缀选择调用次数 | 202 |
| 模型前缀被选中的样本次数（可重复计数） | 169 |
| 参数是否改变 | 是 |
| 训练执行耗时 | 37.01 秒 |
| PyTorch 峰值 allocated | 2,438,173,184 bytes，约 2.27 GiB |
| PyTorch 峰值 reserved | 2,732,589,056 bytes，约 2.54 GiB |
| 辅助 held-out flow objective，训练前 | 1.7152809352 |
| 辅助 held-out flow objective，训练后 | 1.3540775850 |

辅助检查采用同一批 8 条真实 test 动作、同一噪声种子 4242、真实动作前缀和单个 50 帧 primitive，比较官方 flow loss。
这只是小样本、单次训练的教师强制目标检查，不能等价于 FID、语义匹配、长期动作质量、物理跟踪误差或抗扰动成功率。
表中的显存是本进程 PyTorch 指标，不是整张 GPU 的使用量，也不能推算完整 batch128 训练所需显存。
37.01 秒涵盖该脚本的初始化、辅助检查和写检查点等过程，不能当作标准吞吐基准。

原始证据：`../results/pilot_v1/run_receipt.json`、逐步标量 `training_metrics.jsonl`、完整 stdout/stderr、官方 args.json。

## 6. 检查点与低层策略核验

官方 step=100 的保存发生在第 101 次更新后，所以文件名为 `model000000100.pt`，其优化器状态不是只更新 100 次。

| 文件 | 字节数 | SHA256 |
|---|---:|---|
| model000000100.pt | 428,870,124 | `0800452b89d765569d8d1457a5f49a8042d9d8a2c12f7c65145ccea411f291d2` |
| opt000000100.pt | 852,468,483 | `91fee6849637282cb490bb20d370930934473e9d9729f3ccf747a1728ec211ac` |

本地与服务器逐字节哈希一致。CPU 重新构建官方模型并加载该检查点，允许缺失冻结文本编码器的 100 个键，非文本参数没有缺失/多余键。
重新加载后的可训练参数 SHA256 为 `08cf4f1039dcc147b60220b9ed41d529bcf81f8aa91df0348d91f0f6c06586f6`，与训练结束记录一致；365 项优化器状态的 step 均为 101；前向输出 `[1,36,1,50]` 且数值有限。
见 `../results/checkpoint_reload_v1/`。冻结 DistilBERT 需沿用单独缓存。

低层权重使用 [ScaleBFM 官方仓库](https://huggingface.co/WeishuaiZeng/ScaleBFM)，固定 revision `2eec74e0f326076a706702654168efc489ef604a` 的 M 模型，72,856,655 字节，SHA256 与发布 LFS 对象一致。
通过官方 `export_scalebfm_tensorrt.py --dry-run`：模型重建、qpos 适配、策略前向均成功，输出为两个 `[1,29]` 张量。
**dry-run 不执行动力学仿真，也不生成 TensorRT 引擎**，不能写成机器人已成功跟踪动作。见 `../results/tracker_cpu_v1/`。
